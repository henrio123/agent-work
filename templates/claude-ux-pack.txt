GOAL
Produce a UX audit of the booking flow for ticket {{TICKET_ID}}.
Identify friction points, accessibility issues, and competitor parity gaps.
Output a structured audit that the Architect can use to inform the technical design.

NON GOALS
Do not propose technical implementations or architecture decisions.
Do not write code or patches.
Do not change the PM brief scope or acceptance criteria.

INPUTS ALREADY PRESENT
Read {{RUN_FOLDER}}/10-pm-brief.json for scope, acceptance criteria, and constraints.
Read {{RUN_FOLDER}}/00-intake.json for original ticket details.
If available, read .claw/context/booking-flow.context.json for route map, component graph, i18n keys, analytics events, and UX signals.
If available, read .claw/artifacts/pm/{{TICKET_ID}}_scope.json for in-scope routes.

STOP CONDITION BEFORE WORK
If 10-pm-brief.json is missing, stop and report. PM must complete first.

STEPS
1. Read the PM brief to understand scope, constraints, and success metrics.
2. Read the context pack (if available) to understand routes, components, and existing UX signals.
3. For each in-scope route/page, analyze:
   a. User flow: what actions are available, what decisions the user must make
   b. Friction signals: forms, validation, error states, loading states, disabled states
   c. Mobile-first considerations: touch targets, viewport constraints, scroll depth
   d. i18n/copy: are translation keys descriptive, is copy clear across locales
   e. Accessibility: keyboard navigation, screen reader hints, contrast
4. Rank friction points by severity (critical/high/medium/low) with evidence (file paths, component names, event names).
5. Compare against competitor benchmarks (if audit data exists in .claw/ or audit/).
6. Produce the structured UX audit artifact.

VERIFICATION
The output file must validate against the ux-audit schema.
All required fields must be present.
Each finding must reference at least one evidence pointer (file path or component name).
